# 创建「壁纸视觉与性能验收」skill

请在天光天气壁纸 Agent 项目中使用 $skill-creator，创建 `skills/wallpaper-qa`。当用户要求检查生成的天气壁纸、对比两个版本、测量资源占用或发布前验收时触发。它应能接收一个现有作品目录，独立运行检查并输出可复核的结论。交付中文 SKILL.md、必要的检测脚本和一份实际样例报告。发现问题时保留原作品，记录最小复现步骤。

## 输入与运行方式

读取原图或带原图的预览、分区 manifest.json、物理 handoff.json、天气方案、壁纸预览.html，以及可用的 macOS 应用。新版材质或动画 skill 已提供 `materials.json`、`motion.json` 时，用其中的输入指纹、图层顺序、随机种子和采样时间；检查旧作品时，只执行有证据支持的项目。优先从实际交付入口运行。桌面进程测试使用隔离预览或专用测试实例，保留用户正在使用的壁纸。

## 要查出的具体问题

1. 输入一致性。检查原图与分区指纹、尺寸、EXIF 方向、文件完整性。验证原始类别图、对应分组和覆盖范围，防止拿另一张图的蒙版渲染。
2. 表面效果。按现象分别比较透明材质层与物理蒙版，统计 0 区和 127 区的非零 alpha 像素数并标出坐标。分别检查积雪、积水与普通湿润，避免把天空中的飘雪或路面的正常湿色误报成积留越界。抽查车顶、车窗、树梢、草坪与题字边缘，提供同尺度的原图、参考区和成品局部对照。
3. 动画与交互。遍历作品实际支持的天气档，包括四档雪；检查切换残留、前后景遮挡、落点与水纹、窗口缩放、隐藏恢复和减少动态效果。固定时间和种子时比较同一帧；缺少这些接口时，改用时序与位置容差，并注明方法。静态预览与桌面应用分别记录验证结果。
4. 性能。记录机型、系统、浏览器或宿主、屏幕分辨率、刷新率、目标帧率及观察时长。本地开启无降水基线，再在相同视口下测大雨和暴雪。建议各预热 10 秒、采样 60 秒并重复；保留采样参数和原始数据。记录实际帧间隔、P95、CPU 和内存，注明测到的是绘制回调、提交帧还是实际显示帧。macOS 上区分主进程、WebContent 和可归属的 GPU 进程；能可靠取得时才报告 GPU 内存。Apple Silicon 的统一内存总量、进程 RSS 和 GPU 分配量要分别标注。不可归属的指标写“未测得”并说明原因。
5. 本地交付。验证 HTML 离线打开、应用资源齐全、签名状态、可用的预览模式和退出行为。定位或网络天气不可用时，实际检查本地预览是否还能工作，并区分未测条件与真实失败。

## 输出与自测

生成 `qa-report.json` 和人可读的验收报告。每项记录「通过／失败／未测」、期望、实测、证据文件、复现命令或操作步骤。性能判定优先采用用户给定预算或版本基线；没有基线时给实测结果和测量范围。视觉差异要指明天气、区域和位置，可用裁图和连续帧作为证据。

用一份正常作品和它的临时副本验证检查器。在副本里制造两种已知故障，例如把一小块雪层 alpha 写入 127 区、或让涟漪在竖屏裁切后错位，确认报告能命中具体区域。最后提供一次干净作品的实测和一次故障检出结果。
